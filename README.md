# 00CaptureDate v0.3.0 (macOS 13+, Apple Silicon + Intel)

촬영일자 신뢰도를 먼저 판단하고, 대량의 사진·RAW·영상을 **원본 이름 변경**하거나 **다른 위치로 복사**하는 macOS용 독립 앱입니다. 구 00Favorite / My Tangerine의 이름 변경 규칙을 참고한 독립 구현입니다. 기존 HK13 전체 소스와 byte-for-byte 동등성은 현재 증명되지 않았습니다.

## v0.3.0 — 폴더 구성 방식 추가 (v0.2.0 기능·아이콘 유지)

두 가지 독립된 선택 항목을 제공합니다. 이전 버전과 같은 결과를 원하면 기본 설정인 **기존 / 지정 폴더**를 유지하세요.

| 작업 방식 | 폴더 구성 | 예시 동작 |
|---|---|---|
| 원본 이름변경 | 기존 / 지정 폴더 | 원본 위치에서 파일명만 변경 (기존 방식) |
| 원본 이름변경 | 촬영일자별 폴더 | **각 원본 파일이 있던 폴더** 아래 날짜 폴더 생성 후 파일을 이동하면서 이름변경 |
| 새 위치에 복사 | 기존 / 지정 폴더 | 선택한 복사 대상 폴더로 이름변경된 복사본 작성; 필요하면 `원래 폴더 구조 유지` |
| 새 위치에 복사 | 촬영일자별 폴더 | **복사 대상 폴더** 아래 날짜 폴더를 만들고 이름변경된 파일을 복사 (원본 유지) |

**폴더명 양식** 기본값: `{YYYY}년/{MM}월/{YYYY}.{MM}.{DD}_`

2026년 11월 20일 14:30:25에 촬영한 `DSC3015.ARW`를 기본 파일명 양식으로 정리하면:

```text
2026년/
  11월/
    2026.11.20_/
      20261120_143025_DSC3015.ARW
```

- `/`는 하위 디렉터리 구분자입니다. `"년"` 같은 큰따옴표 감싼 고정 텍스트도 지원합니다. 예: `{YYYY}"년"/{MM}"월"/{YYYY}"."{MM}"."{DD}"_"` 는 위와 동일합니다.
- 지원되는 폴더 토큰: `{YYYYMMDD}` `{hhmmss}` `{YYYY}` `{MM}` `{DD}` `{hh}` `{mm}` `{ss}`. 고정 텍스트나 `_`, `.`을 함께 써도 됩니다. **`*`는 날짜 폴더 기호가 아니므로 사용하지 말고 `_`를 직접 입력하세요.**
- 날짜별 모드에서는 복사 원본의 복잡한 기존 하위 경로를 중복 보존하지 않고 **선택한 목적지 + 날짜 폴더 구조**로 정리합니다. 반면 원본 이름변경은 원래 폴더별로 날짜 트리가 만들어집니다.
- **촬영일자 판정 로직은 v0.2.0과 동일**합니다. 날짜가 없거나 `확인 필요`인데 승인하지 않은 파일은 이름변경/복사/이동 모두 건너뜁니다.
- 파일명 양식은 기존 기능을 그대로 사용하며, 촬영일자 폴더와 별개로 설정합니다. 최종 저장 경로를 UI에서 미리 확인하고 `충돌·규칙 사전 검사`를 실행하세요.
- 원본과 복사본의 덮어쓰기는 모두 금지됩니다. 날짜 폴더 생성은 **실제 파일 처리 시점**에만 수행되며, 분석·사전검사에서는 폴더를 만들지 않습니다.
- **이미 이름 변경한 파일:** v0.2.0에서 기본 양식으로 이름을 바꾼 파일은 날짜 폴더 정리 시 기존 이름을 유지한 채 폴더로 옮깁니다. 이미 같은 날짜 폴더 안에 있는 파일은 추가로 중첩하지 않습니다.
- **원본 이동의 안전성:** 자동 생성하는 폴더의 경로를 제한하고 중간 경로의 심볼릭 링크를 확인합니다. 원본 이름변경에서 다른 볼륨으로 복사·이동하도록 변경하지 않습니다.
- **SQLite 복원:** 날짜 폴더로 옮긴 원본 파일과 사이드카도 원래 경로와 파일명으로 복원합니다. 앱이 만든 빈 날짜 폴더는 복원 후에도 남을 수 있으나 원본 파일·다른 내용이 든 폴더는 제거하지 않습니다. 복사 모드의 복원은 기존처럼 **복사본을 해당 폴더 안에서 원래 basename으로 이름 변경**하며, 원본 파일은 그대로 둡니다.
- 1~30일 기록 자동 삭제/즉시 비우기, ExifTool 단일 프로세스, 순차 복사 및 SHA-256 검증, 아이콘 연결은 v0.2.0 그대로 유지합니다.

**테스트:** 날짜별 폴더 생성, 인용부호 구문, 경로 탈출 방지, 심볼릭 링크 차단, 원본 이동과 사이드카, 원본 그대로 복사, SQLite 이름+경로 복원, 기본 메타데이터 판정 테스트를 통과했습니다. 실제 macOS SwiftUI 컴파일과 대량 실기 테스트는 GitHub Actions 빌드 뒤 확인해야 합니다.

## v0.2.0 개선 사항 (v0.1.0의 촬영일자 판정 유지)

- **ExifTool 재사용:** 촬영일자 분석 중 ExifTool 한 프로세스를 `-stay_open True -@ -`로 유지하면서 기존 48개씩 순차 분석합니다. 타임아웃·비정상 응답·특수 파일명 시에는 기존 0.1.0의 개별 배치 실행 방식으로 되돌아갑니다. 별도 빠른/정밀 모드는 없습니다. ExifTool 13.64 고정, EXIF/QuickTime/Sony XML/신뢰도 판정 로직은 변경하지 않았습니다.
- **SQLite 작업 이력:** 실행 직전에 파일별 원본·결과 경로 및 사이드카 정보를 디스크에 기록합니다. 파일 완료 후 결과의 파일시스템 번호/파일 번호/크기/수정시각을 갱신합니다. 프로그램을 종료하고 다시 실행해도 성공한 작업의 원래 파일명을 복원할 수 있습니다.
- **선택 복원 / 작업 전체 복원:** 메인 화면 아래 `작업 기록 · 복원`을 클릭합니다. 원래 이름이 이미 존재하거나 파일 동일성이 맞지 않으면 해당 파일은 **건너뛰고 오류를 표시**합니다. XMP/XML 등의 사이드카도 함께 복원하며 도중 실패 시 완료된 이동은 롤백을 시도합니다. 원래 파일명을 되찾는 것이지, 사진/영상 내용이나 메타데이터를 변경하지 않습니다.
- **복사 모드 복원:** 원본은 그대로 유지합니다. 복사된 파일에 대해서만 복사 위치에서 원래 basename으로 **이름변경**합니다. 원본을 삭제하지 않으며 복사본 자체를 삭제하지도 않습니다.
- **자동 정리 기간 1~30일:** `작업 기록 · 복원` → `작업 기록 자동 삭제`에서 1~30일 선택 (초기값 30일, 설정은 재실행 후에도 유지). **작업 종료 시점 기준** 만료된 작업 세션의 DB 행과 새 버전에서 생성한 연결 JSONL 기록만 삭제합니다. 앱 시작·작업 종료·앱 실행 중 약 1시간마다 정리하며, 앱이 완전히 종료된 동안에는 별도 백그라운드 서비스가 실행되지 않아 다음 실행 때 정리합니다. `작업 기록 바로 비우기…`는 확인 후 모든 작업 이력을 즉시 삭제합니다. **이력 삭제는 사진/영상 파일을 손대지 않지만 해당 파일의 자동 이름 복원은 더 이상 불가능합니다.**
- **중단·복구 안전성:** 실행 전에 SQLite에 `pending`을 먼저 기록해 비정상 종료로 결과 기록이 누락될 경우 감지할 수 있습니다. `pending`, `restoring`, `needs_review`는 자동 복원 대상이 아니며 직접 파일 상태를 확인해야 합니다. 앱의 자체 SQLite 파일을 다른 프로그램에서 지우거나 편집하지 마세요.
- **순차 복사 및 SHA-256 검증 유지:** 병렬 복사나 검사 생략, UI 썸네일, 빠른/정밀 검사 모드 등을 추가하지 않았습니다. 분석/실행 2단계도 기존 그대로 유지합니다.

**0.1.0 이력과의 차이:** 예전 버전에서 만들어진 JSONL 로그는 새 SQLite로 자동 이관하지 않으며, 0.1.0 기록만으로는 자동 복원을 제공하지 않습니다. 과거 JSONL 파일은 그대로 유지됩니다. 새 버전의 자동 정리/비우기는 해당 DB에 등록된 작업과 연결 로그만 정리합니다.

**안전한 테스트 권장:** 먼저 복제한 사진·영상 3~5개로 이름 변경 → 앱 종료/재실행 → 일부 복원 → 전체 복원 → 보존기간/즉시 비우기까지 검증한 다음 실제 원본에 사용하세요. 개발 환경에서는 Swift 핵심 로직과 모의 ExifTool 응답 테스트를 실행했지만 실제 Mac GUI 컴파일 및 100~200GB 장시간 처리 실기는 GitHub Actions와 사용자 환경에서 추가 검증이 필요합니다.


## 순서

1. `파일·폴더 추가`에서 파일 여러 개 또는 상위 폴더 하나를 선택합니다. Finder에서 200GB 전체를 선택하고 액션 휠에 드래그할 필요가 없습니다.
2. `촬영일자 분석`을 클릭하고 각 파일의 날짜·출처·신뢰도를 확인합니다.
3. `원본 이름변경` 또는 `새 위치에 복사`, 그리고 `기존 / 지정 폴더` 또는 `촬영일자별 폴더`를 선택합니다.
4. 날짜별 정리라면 폴더명 양식을 편집하고, 파일명 양식도 원하는 대로 설정합니다. 파일명 기본값: `{YYYYMMDD}_{hhmmss}_{Originalname}`. `Originalname`은 확장자를 제외한 원본 파일 이름입니다. 원래 확장자는 항상 자동으로 붙습니다.
5. `충돌·규칙 사전 검사`를 클릭합니다. 정확한 일시를 못 읽은 파일과 이름 충돌 파일은 작업 대상에서 제외됩니다.
6. `작업 시작`. 일시정지·중단은 파일 경계에서 이루어집니다. 복사 중 중단되면 임시 파일을 삭제합니다.

### 파일명 토큰

`{YYYYMMDD}` `{hhmmss}` `{YYYY}` `{MM}` `{DD}` `{hh}` `{mm}` `{ss}` `{Originalname}` `{filename}` `{ext}` `{SEQ}`. `{SEQ}`는 입력 파일 전체 순서 기준 4자리 번호입니다. `{ext}`를 중간에 넣으면 원래 확장자가 끝에 추가되고, `{filename}.{ext}`처럼 끝에 넣으면 이중으로 추가하지 않습니다.

### 촬영일자 판정 정책

- JPEG, HIF, HEIC, ARW 등 사진·RAW: `ExifIFD:DateTimeOriginal` 최우선. 원본 EXIF를 편집하지 않음. EXIF가 없으면 제조사 기록·XMP 등은 **확인 필요**.
- MOV, MP4, MTS 등 영상: 명시적으로 `+09:00` 같은 시간대가 있는 `Keys:CreationDate` 등을 우선. 같은 클립의 Sony XML (`C0001.MP4` ↔ `C0001M01.XML` 포함)에 시간대가 명시돼 있으면 사용. 서로 일시가 다르면 **확인 필요**.
- QuickTime `CreateDate`, `MediaCreateDate` 등에서만 읽은 시각은 UTC/로컬 해석이 애매하므로 **확인 필요**. UTC `Z`만 있는 태그는 촬영 장소의 현지시각이 분명하지 않으므로 자동 확정하지 않음.
- Finder의 파일 생성일/수정일은 촬영일시 자동 판정에 사용하지 않음.
- HIF·ARW 지원 목록은 GitHub CI 검사에서 고정 확인.
- `확인 필요`는 행 체크박스를 직접 체크해야 이름을 바꿀 수 있습니다. `수정`으로 수동 일시 입력 가능. 기록에는 자동 판정과 구별됨.
- Sony XML 연동은 파일명이 같은 XML 및 Sony의 `M01`, `M02`, `S01` 접미어가 붙은 XML을 지원합니다. 다른 폴더에 있거나 파일명 매핑이 다른 비표준 XML은 자동으로 연결하지 않습니다.

### 100~200GB 안정성

- 메타데이터는 ExifTool 한 프로세스 유지 + 48개 파일씩 일괄 읽기; 실패 시 예전 배치 방식으로 전환. 전체 원본 데이터 메모리 적재 금지.
- 목록은 페이지당 400개 표시; 모든 결과는 순서대로 보관.
- 원본 이름변경은 기본적으로 제자리에서 이름변경하고, 날짜 정리 선택 시 **원래 부모 폴더 안에서** 새 날짜 하위 폴더로 이동합니다. `.xmp`/`.xml` 같은 이름의 사이드카도 함께 이동하고 문제 발생 시 롤백을 시도합니다.
- 복사는 대상 볼륨의 여유 공간이 원본 총량보다 적으면 사전 중단합니다. 같은 폴더에 `.00CaptureDate-*.partial` 임시 파일을 만든 뒤 `SHA-256(원본) == SHA-256(복사본)` 검증 후 최종 파일명으로 이동. 결과 파일이 존재하면 절대 덮어쓰지 않음.
- `작업 기록 · 복원`에서 SQLite 이력 조회 및 선택·전체 복원. `JSONL 로그 보기`로 `~/Library/Application Support/00CaptureDate/logs/run_*.jsonl`도 확인 가능. 성공·오류·경로·SHA를 남김.
- 충돌·미확인·이름 중복 항목은 자동 건너뛰므로 같은 패턴에서 대상 파일명이 중복되면 `{Originalname}` 또는 `{SEQ}`를 사용하세요.
- 대용량 복사에서는 원본 SHA 계산과 복사본 SHA 검증 때문에 처리량보다 검증을 우선합니다. APFS 복제 최적화는 볼륨과 FileManager 동작에 따라 달라집니다.
- SQLite에 기록된 **성공한 이름변경 작업은 앱을 종료/다시 실행한 뒤 복원할 수 있습니다.** 다만 비정상 종료된 미완료 작업을 자동으로 이어서 처리하지는 않습니다. pending/파일 상태를 확인하세요. 예기치 않은 종료로 남은 숨김 `.partial` 파일은 로그와 대조 후 수동 정리해야 합니다.
- 파일 복사 작업 도중 갑작스러운 정전·강제 종료는 시스템이 쓰기를 완료한 데이터까지 보장하지 못합니다. 중요 자료는 다른 매체에 백업 후 사용하세요.

### GitHub에서 빌드

1. GitHub에 새 **Public 또는 Private 저장소**를 만듭니다 (예: `00CaptureDate`).
2. 이 ZIP의 압축을 풀어 내부 파일과 폴더 (`Assets`, `Sources`, `Tests`, `scripts`, `.github`, `.gitignore`, `README.md`)를 저장소 루트에 올립니다. `.github` 폴더는 숨겨져 보일 수 있으니 Finder에서 `Command + Shift + .`로 표시하세요.
3. `Actions` → `Build 00CaptureDate macOS` → `Run workflow`를 실행하거나 `main`에 업로드된 커밋을 기다립니다.
4. 성공한 실행의 `Artifacts`에서 `00CaptureDate-macOS-universal`을 내려받습니다.
5. 압축을 두 번 풀어 `00CaptureDate.app`를 Applications로 옮깁니다.

GitHub Actions는 Apple Silicon(arm64)과 Intel(x86_64)을 합친 **Universal** 앱을 만듭니다. 빌드 도중 ExifTool 13.64 공식 소스 아카이브를 받고 **SHA-256 `dcb9f6be1f6705ee826a92d1522e3fec1d0b3749cdc061b03c46873d5fe204fc`** 검증 후 앱 내부에 포함합니다. 사용자 Mac에는 Homebrew나 ExifTool을 따로 설치하지 않아도 됩니다.

**배포 제한:** Apple Developer ID 공증이 없는 ad-hoc 서명 앱입니다. 처음 실행할 때 macOS에서 차단하면 Finder에서 앱을 Control-클릭 → 열기, 필요한 경우 시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기를 사용하세요. 서명·공증 없이 일반 사용자에게 자동 신뢰되는 앱으로 배포하는 것은 지원하지 않습니다.

### 컴파일 및 테스트 범위

- 플랫폼 종속성이 없는 날짜 파서와 파일명 규칙, `stay_open` 프로토콜, SQLite 원본명 복원·충돌 방지·기간 정리 테스트를 실행.
- macOS 앱 및 GUI는 GitHub Actions macOS 러너에서 컴파일/코드 서명/아티팩트로 검증.
- 실제 Sony HIF/ARW/영상 100–200GB 자료를 이용한 장시간 실기 테스트는 별도로 해야 합니다. 실사용 전에 소수의 복제본으로 날짜·결과를 검사하세요. 테스트 코드는 Sony `M01.XML` 연결, 날짜 신뢰도 게이트, SHA-256 기반 복사 절차, 덮어쓰기 방지, 기본 파일명 중복 적용 방지를 점검합니다.

### 앱 아이콘 연결 (v0.2.0부터 유지)

`Assets/AppIcon.png`는 둥근 모서리 바깥이 투명한 1024×1024 RGBA 이미지입니다.
macOS GitHub Actions에서 `scripts/build-macos.sh`가 PNG를 표준 아이콘셋 크기로 변환한 뒤
`iconutil`로 `00CaptureDate.app/Contents/Resources/AppIcon.icns`를 생성합니다.
앱의 `Info.plist`에는 `CFBundleIconFile=AppIcon.icns`가 등록되며,
**서명과 ZIP 압축 전에** 변환과 검사가 끝납니다.
날짜 판정, ExifTool, SQLite, 이름변경/복사 소스는 변경하지 않았습니다.

v0.3.0은 `Assets/AppIcon.png`를 그대로 포함합니다. 기존 v0.2.0 저장소에 적용할 때는
`Sources/WorkEngine.swift`, `Sources/AppModel.swift`, `Sources/ContentView.swift`, 신규 `Sources/FolderPattern.swift`,
`Tests`의 날짜 폴더 관련 시험, `scripts/test-core.sh`, `scripts/build-macos.sh`를 함께 반영해야 합니다.
`README.md`도 함께 교체하세요. 기존 사용자 수정 사항은 적용 전 백업하세요.
